В наших конфигурациях Workers (`deploy/*.json`) observability не включена. Подробного логирования не добавлять; платные подписки и биллинг — только с разрешения владельца.

## Технический долг

- Релиз: два merge подряд могут выкатиться не по порядку (20.11 #199 опубликовался после #200 и временно откатил его; вернул #201). В publish нет проверки «этот SHA ещё голова main». Merge делать по одному после окончания релиза.

- D1 CORE: триггеры `monitor_runs_link_events_*` (`UPDATE monitor_runs AS m …`) не проходят проверку SQLite при `ALTER TABLE … RENAME` любой таблицы. Сами триггеры работают. Миграции делать через пересоздание таблицы, без RENAME (как `storage/cloudflare/006`).
- Frontend собирается склейкой файлов по `build-order.json`, `import` вырезаются регулярным выражением. Строки i18n зашиты в компоненты. `frontend/tests` и `frontend/scripts` не отформатированы Prettier.
- Legacy `worker/`, `baselines/`, `site/` (~900 КБ) не входят в release. Удалять только с доказательством, что они не используются.

## Границы для любого агента

Без явного разрешения владельца не делать: production merge/deploy, запись в production D1/Neon (preview делит bindings), изменения cron, секретов, платных квот и AI-лимитов, новые Workers, удаление legacy. Разрешение, выданное в чате одному агенту, другим не передаётся.
