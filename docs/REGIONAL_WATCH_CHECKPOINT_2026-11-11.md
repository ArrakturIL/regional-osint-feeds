## ГЛАВНОЕ: последняя согласованная задача

Пользователь хочет **полностью автоматическую редакторскую рубрику с материалами аналитиков**, а не ручную коллекцию цитат и не требующую утверждения очередь черновиков.

**Желаемый сценарий:** выбранный аналитик, например **Ауслендер**, выпускает YouTube-видео, подкаст, интервью, новый Telegram/X-пост или статью. Система сама замечает публикацию, получает её содержимое (видео — доступные субтитры/транскрипция или разрешённое распознавание речи), выявляет темы Израиля, Ирана, США, конфликтов и Ближнего Востока, определяет ценность **для REGIONAL WATCH**, сравнивает с ранее опубликованным, выбирает значимые тезисы/короткие точные цитаты, при достаточном качестве сама публикует запись в отдельной рубрике сайта со ссылкой на оригинал, датой, автором, таймкодами для видео, контекстом и собственными прозрачными оговорками. Малозначимые повторы пропускает. **Без обязательной ручной модерации каждой записи.**

Считать отдельно: (1) подтверждённость авторства/точность цитаты; (2) достоверность фактического утверждения автора; (3) ценность публикации для проекта. Не представлять прогнозы/мнения как подтверждённые факты. Не придумывать транскрипцию, не переписывать длинные защищённые цитаты; использовать краткие цитаты и самостоятельное резюме, сохранять источник. Важны версионность, исправления, предотвращение повторов и след решений ИИ. При недоступности текста/таймкодов не имитировать просмотр: пропускать или помечать запись как недостаточно проверенную.

### Предлагаемая реализация (ПОКА АРХИТЕКТУРА, НЕ ВНЕДРЕНО)

1. **Реестр аналитиков и источников** в отдельной таблице D1: идентификатор автора, официальные YouTube channel ID/Telegram каналы/X-профили/сайты/RSS, языки, темы, состояние/частота опроса; никакие аккаунты Ауслендера пока НЕ верифицированы и НЕ подключены.
2. **Сбор новых публикаций**: GitHub Actions для платформенно ограниченных источников, Cloudflare Cron/Worker для доступных RSS/API. По каждому каналу курсор, source ID, время публикации, ссылка, тип материала; дедупликация по canonical URL и content hash. Не обходить приватность/ToS. Официальный YouTube API не даёт свободного получения субтитров любых чужих видео; планировать разрешённые источники транскрипций или ASR с учётом бесплатных лимитов и прав.
3. **Нормализация текста**: извлечение поста/транскрипта/доступной статьи, язык, точность, таймкоды, время публикации, привязка к оригиналу. Для длинных видео анализ по сегментам с объединением тезисов.
4. **ИИ-редактор**: признаки релевантности Израилю/региону, новизна против истории, содержательность (новые аргументы, факты, прогнозы, проверяемые заявления), надёжность источника текста; возврат структурированного JSON с решением `publish|skip|needs_data`, обоснованием, выделенными фрагментами и ссылками. Оценка пригодности контента, а не политический рейтинг людей; нейтральная атрибуция позиций.
5. **Автопубликация**: защищённый backend writer валидирует структурированный результат, цитаты, source provenance, отсутствие дублей, даты и длины; пишет в отдельные таблицы `analysts`, `analyst_sources`, `analyst_items`, `analyst_editorial_decisions`, `analyst_publications` (названия уточнить после сверки реальной схемы). Отдельный публичный read-only API `GET /api/analysts`, `GET /api/analyst-posts`. Тело и ключи не отдаются на клиент. Удаления/редакционные исправления логировать.
6. **Архитектурное разделение:** эта рубрика независима от основной почасовой задачи США–Иран и от автоматизации «Реплика редактора». **UI ведётся отдельным чатом и здесь НЕ трогать**. Возможно отдельный Worker для редакционной очереди, с использованием существующей D1; решение принять после оценки существующего сайта и API.
7. **Исполнение автономно:** нельзя рассчитывать на то, что одноразовый чат будет работать в фоне; нужен расписанный реальный исполнитель (Cloudflare/GitHub Actions/автоматизация ChatGPT с коннектором), журнал очередей и ошибок, тесты, лимиты, безопасные обновления. Проверить бесплатную пригодность выбранной модели (например Workers AI) для объёма текстов.
