# Regional Watch — навыки GPT

Справочник к инструкции проекта. При расхождении верны инструкция и репозиторий (docs/gpt-automations.md). Разделы независимы: читай нужный. 1 — факт-чек, 2 — досье, 3 — реплика, 4 — перевод, 5 — D1, 6 — отчёты, 7 — оформление, 8 — здоровье сайта, 9 — уроки.

## 1. Факт-чек

### Порядок
1. **Разбери присланное.** Что именно утверждается: кто, что, где, когда, цифры. Разбей на отдельные проверяемые утверждения.
2. **Найди первоисточник.** Официальные: ЦАХАЛ (idf.il, X @IDF / @idfonline), Командование тыла (oref.org.il), канцелярия премьера, МИД и Минобороны стран, CENTCOM, ООН, МАГАТЭ. Для заявлений сторон — их собственные каналы, с пометкой party_claim.
3. **Ищи независимое подтверждение.** Два издания с разными репортёрами. Перепечатка Reuters/AP другими — это всё ещё один источник.
4. **Ищи другую сторону и опровержения.** Израильские, арабские, иранские, западные источники. Свежие опровержения и поправки ищи отдельным запросом.
5. **Проверь время.** Когда произошло событие, а когда опубликована новость. Старое событие, поданное как новое, — частая подмена.
6. **Проверь медиа.** Для фото и видео: обратный поиск (Google Lens, Yandex, TinEye), признаки места (вывески, рельеф, погода), первое появление в сети. Видео из прошлых войн и учений — частая подмена.
7. **Вынеси вердикт** по шкале ниже.

### Шкала вердикта
| Вердикт | Когда |
|---|---|
| Подтверждено | первоисточник или ≥2 независимых издания, без весомых опровержений |
| Частично | ядро верно, детали (цифры, место, атрибуция) неверны или не подтверждены |
| Заявлено одной стороной | есть только заявление участника конфликта |
| Не подтверждено | источников нет или они слабые |
| Ложно | опровергнуто первоисточником или фактами (дата, место, медиа) |
| Устарело | было, но давно; подано как новое |

### Красные флаги
- Нет имени источника («источники сообщают», «по данным СМИ»).
- Круглые или слишком точные цифры без первоисточника.
- Только Telegram и X, крупные СМИ молчат дольше часа при громком событии.
- Эмоциональные заголовки, «шок», «срочно» без деталей.
- Скриншот новости без ссылки.
- Совпадение с прошлогодним событием (то же место, похожие цифры).

### Шаблон ответа в чате
```
**Вердикт:** <одна строка>

**Известно точно:** <кто, что, где, когда, цифры>

**Источники:**
- <издание/ведомство> (official|party_claim|media) — <ссылка>

**Расхождения:** <что спорно и почему>

**Контекст:** <2–3 предложения>

**Неизвестно:** <что не проверено>

**Для сайта:** <досье / реплика / ничего>; уже есть: <id или нет>. Жду «да».
```

## 2. Досье (monitor_events)

### Когда делать
- Событие подтверждено (первоисточник или ≥2 независимых).
- Его ещё нет в monitor_events: сверяй тему, место и дату, а не формулировку.
- Значимо для безопасности региона: удары, перехваты, решения правительств и армий, закрытие воздушного пространства, эвакуации, крупные теракты, переговоры с реальным результатом.
- Не делать: колонки, аналитику, подкасты, интервью без новой информации, повтор вчерашнего.

### Заголовок title_ru (≤240)
Конкретно: кто, что, где. Без оценок и кликбейта.
- Хорошо: «ЦАХАЛ нанёс удары по объектам «Хезболлы» в долине Бекаа после ракетного обстрела Галилеи»
- Плохо: «Новая эскалация на севере»

### Текст summary_ru (≤1050)
1. Что произошло: факты, время по Израилю, место.
2. Кто подтвердил: «по данным ЦАХАЛ», «сообщили Reuters и Times of Israel».
3. Что заявляют стороны (с атрибуцией).
4. Чего пока не известно.

### Поля
- `first_seen` — дата события `ГГГГ-ММ-ДД` (как в существующих записях). Это не время записи.
- `updated_at_ms` — время записи, сейчас. По нему сайт сортирует досье и по нему считается «досье старше 24 ч».

### sources
Первым — первоисточник. Каждой записи — `kind` и `publisher`. Не больше 5–6 ссылок.

## 3. Реплика редактора (editorial_notes)

### Чек-лист перед записью
- [ ] Факт подтверждён (первоисточник или 2 издания).
- [ ] Тема не повторяет последние реплики (topic_key за 24 ч).
- [ ] Мишень — институт, политик, пиар, бюрократия; не жертвы, не народ, не религия.
- [ ] Нет выдуманных цитат и искажённых фактов.
- [ ] headline ≤90 знаков, text ≤400, 1–3 предложения.
- [ ] verified_note: что и по каким источникам проверено.
- [ ] Иврит записан сразу (kind='editorial', model='gpt-editor').

### Приёмы
Сухая констатация с уколом в конце, сравнение обещания и результата, буквальное прочтение пресс-релиза. Сарказм в иврите — свой, не перевод русского.

## 4. Перевод RU/HE: справочник

### Термины
| EN | RU | HE |
|---|---|---|
| IDF | ЦАХАЛ | צה״ל |
| Chief of Staff | начальник Генштаба | רמטכ״ל / ראש המטה הכללי |
| Home Front Command | Командование тыла | פיקוד העורף |
| Shin Bet | ШАБАК | שב״כ |
| Iron Dome | «Железный купол» | כיפת ברזל |
| David's Sling | «Праща Давида» | קלע דוד |
| Arrow 2/3 | «Хец-2/3» («Стрела») | חץ 2/3 |
| Iron Beam | «Железный луч» | אור איתן |
| IRGC | КСИР | משמרות המהפכה |
| Quds Force | силы «Кудс» | כוח קודס |
| Houthis | хуситы | החות׳ים |
| Palestinian Islamic Jihad | «Исламский джихад» | הג׳יהאד האסלאמי |
| CENTCOM | Центральное командование США | פיקוד המרכז האמריקאי |
| UNIFIL | ВСООНЛ / миротворцы ООН | יוניפי״ל |
| Knesset | кнессет | הכנסת |
| hostages | заложники | חטופים |
| displaced | вынужденные переселенцы | עקורים / מפונים |
| ceasefire | прекращение огня | הפסקת אש |

### Звания ЦАХАЛ
רס״ן — майор, סא״ל — подполковник, אל״מ — полковник, תא״ל — бригадный генерал, אלוף — генерал-майор, רב-אלוף — генерал-лейтенант.

### Частые ошибки
- Дословщина: «перемещённые лица», «нанёс удар по целям террора» → «вынужденные переселенцы», «нанёс удары по объектам боевиков».
- Ракета ≠ беспилотник ≠ снаряд. «Rocket» (неуправляемая) и «missile» (управляемая/баллистическая) не смешивать.
- «Ликвидирован» и «убит» — не синонимы для атрибуции: ЦАХАЛ пишет «ликвидирован», нейтральная подача — «убит, по данным ЦАХАЛ».
- Числа погибших и раненых — с источником: «по данным Минздрава Газы, подконтрольного ХАМАС».
- Иврит: никакой ASCII-кавычки в аббревиатурах (צה"ל → צה״ל), никакой кириллицы и арабицы.

## 5. D1: готовые запросы

Правила: ≤30 запросов за запуск, окно по времени, LIMIT ≤200, индексы через `INDEXED BY`, где они есть. Без `COUNT(*)` и `GROUP BY` по всей таблице. Время в базах — миллисекунды UTC.

### NEWS
```sql
-- важные новости за окно
SELECT id,source,headline,summary,url,priority,published_ms
FROM news_items INDEXED BY news_items_priority_published
WHERE priority>=7 AND published_ms>? ORDER BY published_ms DESC LIMIT 100;

-- группы событий
SELECT event_id,representative_id,topic,priority,last_seen_ms,source_count,origin_count,verification_status,sources_json
FROM news_event_groups WHERE last_seen_ms>? AND priority>=4 ORDER BY last_seen_ms DESC LIMIT 50;

-- последние реплики
SELECT id,topic_key,headline,published_ms FROM editorial_notes WHERE published_ms>? ORDER BY published_ms DESC LIMIT 20;

-- ручная очередь переводов
SELECT kind,item_id,language,source_hash,tier,attempts,payload_json,discovered_ms
FROM translation_jobs WHERE language IN ('ru','he') AND state='manual' LIMIT 30;

-- закрыть своё задание
UPDATE translation_jobs SET state='done',last_reason='gpt',last_model=?,updated_ms=?
WHERE kind=? AND item_id=? AND language=? AND source_hash=?;
```

### CORE
```sql
SELECT event_id,category,first_seen,payload,updated_at_ms FROM monitor_events ORDER BY updated_at_ms DESC LIMIT 30;
SELECT source,state,succeeded_at,detail FROM source_status ORDER BY source LIMIT 200;
```

### Запись перевода (regional_i18n)
Колонки: `kind, item_id, language, source_hash, title, body, commentary, quality_score (85–100), model, created_at_ms`. Ключ — `(kind,item_id,language)`. Используй `INSERT … ON CONFLICT(kind,item_id,language) DO UPDATE SET …`, только если source_hash новый.

### Хэш: пример
```python
import hashlib, json
v = lambda s, n: (s or '').strip()[:n]
LIST = [v(title_ru, 240), v(summary_ru, 1050), '']   # story
h = hashlib.sha256(json.dumps(LIST, ensure_ascii=False, separators=(',', ':')).encode()).hexdigest()
```
Для news — `[headline 260, summary 650, comment 300]`, для editorial — `[headline 260, text 1900, '']`. Если хэш не совпал с заданием — не пиши, отметь в отчёте.

### ops/OPS_STATUS.md (задача №1)
```
# OPS 23.11 14:07 · по расписанию | ручной
Сайт: 200 · /api/news: не пуст | не проверялся
Источники с проблемой: <список или «нет»>
Кандидаты: 4 · новых досье: 1 (rw-…)
Прогон: no_alert | alert | partial — <почему>
Ограничения: <чего не хватило: GDELT неполный, веб-сверка недоступна…> | нет

```
Статус прогона — только `no_alert`, `alert`, `partial` (так же в D1). `partial` — **только** когда не удалось сопоставить новостные источники между собой. Неполный GDELT или недоступная веб-сверка — это не `partial`: статус `no_alert`/`alert` по сути, недостающее — в строку «Ограничения».

Этот файл лежит в репозитории: `docs/gpt/SKILL.md` (ArrakturIL/regional-osint-feeds, ветка main). Задачи по расписанию не видят файлы проекта ChatGPT — читать отсюда.

## 7. Оформление документов и ответов

### Общее
- Сначала ответ или итог, потом детали. Без «отличный вопрос», «давайте разберём».
- Короткие абзацы. Списки — для перечней, таблицы — для сравнений, заголовки — в документах длиннее экрана.
- Факт, вывод, предположение и неизвестное — раздельно и явно.
- Живой язык, без канцелярита: «сайт упал в 14:05», а не «была зафиксирована недоступность ресурса».

### Числа, даты, время
- 1 250; 3,7 млн; 74%; 2,5 с.
- Дата — 23.11 (год, если не текущий: 23.11.2025). Время — 14:05 по Израилю; UTC не писать.
- Диапазоны — через тире без пробелов: 3–4 реплики, 08:00–23:00.

### Документ для владельца
1. Заголовок — что это.
2. Одна строка итога.
3. Суть: что сделано или что предлагается.
4. Доказательства: что прочитано, проверено или записано (id, ссылки).
5. Граница: что не сделано, что дальше, что ждёт решения.
Размер — до 8–10 КБ, без истории и логов. Подробности — ссылкой.

### Итог этапа
```
**Досье за ночь закрыты.** ✅
Создано 3 (rw-…, rw-…, rw-…), иврит записан, хэши сверены.
Не сделано: 1 кандидат — только заявление ХАМАС, жду подтверждения.
```
`⚠️` — если что-то не так, и сразу что именно.

### Цитаты и ссылки
- Ссылка — на конкретную страницу, не на главную издания.
- Цитата — короткая, с атрибуцией. Длинные куски чужих текстов не копировать — пересказывай.

## 8. Здоровье сайта

GPT **диагностирует, но не чинит**. Код, cron, секреты, лимиты и источники меняет Claude с разрешения владельца. Твоё дело — заметить, доказать и коротко сообщить.

### Что проверять каждый запуск задачи №1 (≤8 запросов)
| Что | Где | Тревожно, если |
|---|---|---|
| Сайт | https://regional-watch.pages.dev/ | не 200 |
| Лента | /api/news?lang=ru&limit=1 | не 200 или пустой `articles` |
| Источники | CORE `source_status` | `state='error'`, или `succeeded_at` старше 6 ч |
| Кэш сборщиков | CORE `regional_collector_cache` (source_key, checked_at_ms, synced_at_ms) | `checked_at_ms` старше двух обычных интервалов источника |
| RSS-ленты | NEWS `feed_status` (name, checked_ms, status, http_status, items_count, error) | `checked_ms` старше 30 мин (Editor ходит раз в 5 мин) или много лент со `status='error'` |
| Переводы | NEWS `editor_state` key `translation_sla` (JSON), `last_translation_error` | срочные просрочены (>15 мин) или ошибка свежее часа |
| Ручная очередь | NEWS `translation_jobs` `state='manual'` LIMIT 30 | больше 10 заданий |
| Досье | CORE `monitor_events`, **по `updated_at_ms`** | самое свежее `updated_at_ms` старше 24 ч. `first_seen` — дата события, по ней свежесть не мерить |
| Свой прогон | CORE `monitor_runs` | прошлый запуск не записан |

Сайт и API могут быть недоступны твоему инструменту. Тогда пиши «не проверялся» — это не авария.

```sql
-- NEWS: ленты RSS
SELECT name,checked_ms,status,http_status,items_count,error FROM feed_status ORDER BY name LIMIT 50;
-- NEWS: SLA и последняя ошибка перевода
SELECT key,value,updated_ms FROM editor_state WHERE key IN ('translation_sla','last_translation_error');
-- CORE: кэш сборщиков
SELECT source_key,checked_at_ms,synced_at_ms FROM regional_collector_cache ORDER BY source_key LIMIT 50;
-- CORE: свежесть досье (по времени записи, не по first_seen)
SELECT event_id,first_seen,updated_at_ms FROM monitor_events ORDER BY updated_at_ms DESC LIMIT 1;
-- CORE: свои последние прогоны
SELECT run_id,outcome,recorded_at_ms FROM monitor_runs ORDER BY recorded_at_ms DESC LIMIT 3;
```

### Как ставить диагноз
1. **Один факт — одна проблема.** «Лента Ynet: http 403 с 13:20» лучше, чем «что-то с источниками».
2. **Сравни с прошлым отчётом** (ops/OPS_STATUS.md). Новая проблема, давняя или прошла сама?
3. **Отличай сбой источника от сбоя сайта.** Одна упавшая лента — норма жизни, сайт живёт. Пустая лента новостей — авария.
4. **Не предлагай лечение наугад.** Пиши, что видно, и что проверить дальше Claude: таблица, поле, время.
5. **Ленты на паузе** (JNS, Arutz Sheva, Guardian, Al-Monitor, Israel Hayom) отключены владельцем. Это не сбой и не повод для отчёта.

### Уровни
- **Норма** — пишешь только в OPS_STATUS.md.
- **Внимание** — в OPS_STATUS.md раздел «Проблемы» с фактами; владельцу не пишешь.
- **Авария** (по инструкции: сайт или API не 200 два запуска подряд, пуст /api/news, все досье старше 24 ч, запись в D1 не проходит два запуска подряд) — одно сообщение владельцу:
```
⚠️ Regional Watch: <что сломано>
С: <время по Израилю> (запусков подряд: 2)
Видно: <факт, таблица/URL, код ответа>
Проверить: <что дальше — для Claude>
```
Повторно о той же аварии — не чаще раза в 6 ч, пока она не изменится.

### Бюджет D1
Твои запросы — часть общего лимита 5 млн строк в сутки. Если сайт сам приблизился к лимиту (тревога в отчёте использования), сокращай свои чтения до минимума: здоровье + поиск событий, без лишних проверок.
