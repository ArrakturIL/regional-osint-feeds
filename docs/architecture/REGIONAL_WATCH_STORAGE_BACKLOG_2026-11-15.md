# REGIONAL WATCH — отложенное решение по хранилищу данных (15.11.2026)

## Решение пользователя
**Отложить выбор новой бесплатной базы/объектного хранилища.** Сейчас не подключать R2, не регистрировать платные сервисы и не менять действующие сборщики. Приоритет: завершить рефакторинг, объединить `refactor/regional-watch-modular-20261114` с `main`, опубликовать обновлённый сайт и выполнить QA.

## Контекст
- GitHub Actions регулярно записывают обновляемые JSON в `main`: GDELT, Copernicus, зеркала аналитиков, локализации, другие публичные источники. Так появляются автоматические коммиты и возможные гонки `git push`.
- GitHub — архив кода и файлов, но не предпочтительное хранилище для часто изменяемых данных.
- Уже работает Cloudflare D1; хорош для структурированных записей, индексов и запросов.
- Cloudflare R2 рассматривался для сырого JSON, снимков API и архивов. **Фактическая проверка API 15.11.2026 вернула HTTP 403 code 10042 (R2 not enabled)**. Включение R2 может потребовать биллинг; пользователь решил пока не подключать.
- Альтернативы — бесплатные тарифы других DB или object storage, либо усовершенствование использования существующего D1. **Никакого сервиса пока не выбрано.**

## Вернуться после QA
1. Измерить объём JSON, периодичность обновлений, число read/write запросов, срок хранения и условия публичного доступа.
2. Проверить реально доступные бесплатные (без обязательной оплаты) варианты по ограничениям, безопасности, резервированию и способу доступа из GitHub Actions/Workers.
3. Решить, какие объекты хранить в D1, какие в объектном хранилище, а какие оставить в GitHub как редкие фиксированные снимки.
4. Спроектировать миграцию без потерь и с откатом; исключить параллельную запись в `main`.
